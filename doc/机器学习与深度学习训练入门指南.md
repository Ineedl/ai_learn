# 机器学习与深度学习训练入门指南

> 面向设备：NVIDIA RTX 4060 Ti 16GB 显存 + 32GB 系统内存。  
> 文档语言：中文。建议投入：每周 6～10 小时，连续 8 周。  
> 默认起点：有后台开发经验，熟悉 Python 或能快速读写 Python；不从 Python 语法、函数、类等基础开始。机器学习基础较少；数学按需补齐。

## 1. 先明确目标和设备能力

你的配置足够学习经典机器学习、训练小型图像分类网络、使用预训练模型做迁移学习，以及在后续尝试小型语言模型的参数高效微调。建议先完成本文三个实战，建立完整的训练、验证、测试流程，再接触大模型。

“训练”是根据样本调整模型参数；“推理”是用训练好的参数对新样本进行预测。能运行一个模型，并不代表有足够资源从头训练它。

| 项目 | 这套设备的适用情况 | 入门建议 |
| --- | --- | --- |
| 表格分类、回归、聚类 | 很合适，通常 CPU 就够 | 从 scikit-learn 开始 |
| 小型 CNN 图像分类 | 很合适 | 使用 PyTorch，理解训练循环 |
| ResNet 等图像模型迁移学习 | 很合适 | 先冻结骨干网络，只训练分类层 |
| 小型 Transformer、中文文本分类 | 合适，取决于序列长度和批量 | 完成前三个项目后扩展 |
| Stable Diffusion 的 LoRA | 部分模型和配置可行 | 作为后续专题，需要单独规划 |
| 7B 级语言模型量化推理或 QLoRA | 部分配置可行，不能保证任意模型都能跑 | 要控制上下文长度、批量及软件配置 |
| 从零预训练大型语言模型、全参数微调大模型 | 不适合作为单卡入门任务 | 先学习小模型和迁移学习 |

注意两个容量不同：**16GB 显存**保存 GPU 上的模型、激活、梯度和优化器状态；**32GB 内存**用于操作系统、数据加载和 CPU 计算。内存不能直接等价替代显存。模型权重大小也不等于训练时显存占用。

磁盘建议预留约 50～100GB，最好使用 SSD。实际占用取决于数据集、框架安装包、缓存和模型检查点。

## 2. 学习顺序：先跑通，再理解，再改进

推荐主线：

```text
Python 数据科学生态速查（NumPy / pandas / sklearn API）
        ↓
数据切分、基线、评价指标与实验规范
        ↓
经典机器学习：预处理 + 逻辑回归 / 随机森林
        ↓
PyTorch：张量、自动求导、训练循环
        ↓
CNN 图像分类 + 保存和加载模型
        ↓
迁移学习 + 实验记录 + 错误分析
```

暂时不需要同时学习 TensorFlow 和 PyTorch。先熟悉 PyTorch，减少环境和概念切换。

### 必须理解的概念

| 概念 | 通俗理解 | 在实战里做什么 |
| --- | --- | --- |
| 特征、标签 | 输入信息与希望预测的答案 | 确认每个样本的输入和目标 |
| 训练集 | 模型用来学习的数据 | 允许计算梯度并更新参数 |
| 验证集 | 开发阶段比较模型的数据 | 选超参数、选检查点 |
| 测试集 | 最终评估用的数据 | 方案确定后再评价 |
| 损失函数 | 用于优化的错误度量 | 分类常用交叉熵 |
| 优化器、学习率 | 更新参数的方法与步长 | 先用 AdamW，学习率从 0.001 附近尝试 |
| batch size、epoch | 每步样本数量、遍历训练集的轮数 | 调整速度、显存和训练进度 |
| 过拟合 | 训练集表现好，新数据表现差 | 比较训练与验证表现，增加正则化或数据 |
| 数据泄漏 | 训练过程提前接触了评估数据的信息 | 先划分数据，再拟合预处理 |
| 基线模型 | 用来判断新方案是否有效的简单方案 | 先做简单模型，再增加复杂度 |

数学按需学习：向量与矩阵、导数和梯度、均值与方差、概率和交叉熵。每学一个概念，尽量在代码中找到对应位置。你已有后台开发经验，直接从环境检查和数据流程开始；只需熟悉 NumPy 的数组形状/广播、pandas 的表格操作、sklearn 的 estimator/Pipeline 接口，不安排 Python 语法课程。

## 3. 环境安装与检查

### 3.1 操作系统选择

- 已经使用 Linux：直接使用当前系统。
- 使用 Windows：建议 Windows 11 + WSL2 Ubuntu，也可以先使用 Windows 原生 Python。
- WSL2 使用宿主机 NVIDIA 驱动；不要在 WSL 内额外安装 Linux 显示驱动。
- WSL2 中建议把训练项目和数据放在 Linux 文件系统，例如 `~/ml-learning`，避免大量小文件跨 `/mnt/c` 读取。

下面使用 Conda 管理 Python 环境。需要提前安装 Miniconda 或兼容的 Conda 发行版；也可以使用自己熟悉的虚拟环境工具。

### 3.2 先检查驱动

在终端运行：

```bash
nvidia-smi
```

应能看到 RTX 4060 Ti 和显存信息。如果命令失败，先修复驱动或 WSL GPU 支持。输出中的 `CUDA Version` 表示驱动支持的 CUDA 版本上限，不能据此判断本机已经安装了 CUDA Toolkit。

### 3.3 安装 Python 和依赖

```bash
conda create -n ml-start python=3.11 -y
conda activate ml-start
python -m pip install --upgrade pip
python -m pip install numpy pandas matplotlib scikit-learn jupyterlab
```

然后访问 [PyTorch 官方安装页面](https://pytorch.org/get-started/locally/)，选择自己的系统、Pip、Python 和驱动支持的 CUDA 版本。**优先使用页面生成的命令**，不要混用不同来源的 torch 和 torchvision。

例如，下面是 CUDA 12.8 wheel 的一种安装写法；仅在官方页面提供该选项且本机驱动支持时使用：

```bash
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```

官方 CUDA wheel 通常带有所需的 CUDA 运行时。本文项目一般不需要额外安装系统 CUDA Toolkit；编译自定义 CUDA 扩展时才需要另行处理。

检查安装：

```bash
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA runtime:', torch.version.cuda); print('GPU available:', torch.cuda.is_available()); print('Device:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

确认 `GPU available: True`，设备名称正确。本文深度学习代码也支持 CPU 回退，但速度会慢很多。

安装成功后保存环境信息，便于复现：

```bash
python -m pip freeze > requirements-lock.txt
nvidia-smi > gpu-info.txt
```

`pip freeze` 主要记录包版本；另需记录安装 PyTorch 使用的 wheel 来源、操作系统和驱动版本，跨平台复现时重新核对官方安装命令。

### 3.4 建议的练习目录

在你选择的项目根目录创建下面结构。本文代码块需要手动保存到对应 `.py` 文件；本指南本身不会安装依赖或开始训练。

## 4. 8 周分阶段学习计划

这条路线按“每周 6～10 小时”设计。每阶段都要留下可检查的产物；阶段验收未通过时，先补齐对应短板再往后走。可将每周拆成 2～3 次学习：先读概念，再动手实现，最后整理记录并口头复述。

### 阶段 0：环境与数据工具（第 1 周，约 4～6 小时）

**目标：** 建立可复现的实验环境，并熟悉机器学习代码里常见的数据对象，不补 Python 基础语法。

**学习内容：**
- Python 环境隔离、依赖锁定、脚本入口和相对路径；记录 Python、PyTorch、torchvision、sklearn、驱动版本。
- NumPy 的 `ndarray`、`shape`、`dtype`、索引、切片、广播、向量化；理解样本维、特征维、通道维。
- pandas 的读取、缺失值检查、类别/数值列区分、基本统计；Matplotlib 只需能画分布和训练曲线。
- CPU/GPU 张量设备差异；确认数据、模型和标签位于兼容设备。

**动手与产物：** 完成第 3 节环境安装；新建 `outputs/environment.txt` 记录版本与 GPU；用 NumPy 读取一个小数组并打印形状，用 pandas 检查一份表格数据分布。

**如何验证：** `torch.cuda.is_available()` 为 True 且设备名正确；能解释一批图像常见的 `[batch, channel, height, width]` 形状；从干净终端激活环境并运行检查脚本成功。若你已熟悉这些 API，可将本阶段压缩为一次环境检查。

### 阶段 1：数据切分、基线与指标（第 2 周，约 6～8 小时）

**目标：** 能设计可信的离线评估，不把训练分数误当泛化能力。

**学习内容：**
- 特征/标签、样本与类别分布；训练集用于拟合，验证集用于选择，测试集只用于最终报告。
- 随机分层切分；同用户/设备/原始来源的分组切分；时间数据按时间切分。
- 缺失值、标准化、类别处理与 Pipeline；所有需要拟合的预处理只在训练集 `fit`。
- 多数类基线；Accuracy、Precision、Recall、F1、ROC-AUC、混淆矩阵分别回答什么问题。
- 类别不均衡时确定业务正类，避免只看准确率或错误解读默认正类。

**动手与产物：** 完成实战一；把数据划分、随机种子、每个模型的验证指标、所选模型和一次性测试指标写入 JSON/实验记录。

**如何验证：** 能在白板上画出数据流并指出预处理拟合位置；人为把标签随机打乱后，模型分数应接近基线/随机水平；比较逻辑回归和随机森林时只按验证集选型，测试集只评估一次。若随机打乱标签仍得到异常高分，先排查泄漏。

### 阶段 2：经典模型与误差解释（第 3 周，约 6～8 小时）

**目标：** 建立后续深度学习实验的比较基准，理解模型结果来自数据、指标和决策阈值的共同作用。

**学习内容：**
- 逻辑回归的线性决策边界、正则化强度 `C` 与特征缩放；随机森林的非线性能力、树数量与过拟合倾向。
- 验证集调参、交叉验证、均值/波动；不在同一测试集上反复挑参数。
- 分类阈值与 Precision/Recall 权衡；模型概率与分类决策不是一回事。
- 错分样本检查：类别、边界样本、异常值、标签噪声、数据质量。

**动手与产物：** 对实战一做 `C=0.1/1/10` 验证对比；输出混淆矩阵和分类报告；选取至少 10 条错分样本，检查其原始特征。

**如何验证：** 能解释标准化为何影响逻辑回归但通常不影响树模型；能从混淆矩阵读出目标类别的漏报/误报；用验证集选择阈值后，在测试集仅报告一次结果。产物至少包含基线、一个改动、验证对比和结论。

### 阶段 3：PyTorch 张量、自动求导和训练循环（第 4 周，约 8～10 小时）

**目标：** 不依赖高层 Trainer，能够读懂和调试标准训练循环。

**学习内容：**
- Tensor 的 shape、dtype、device；`Dataset`、`DataLoader`、batch 与 shuffle。
- 模型参数、前向传播、logits、交叉熵；分类标签为何通常是整数类别索引。
- 计算图、梯度、链式法则直觉；`zero_grad → forward → loss → backward → step` 的职责。
- `train()` / `eval()`、`no_grad()` / `inference_mode()`；Dropout 和 BatchNorm 的模式行为。
- 学习率、batch size、epoch、优化器；训练/验证 loss 的记录。

**动手与产物：** 先用 Fashion-MNIST 的少量批次验证数据形状、输出维数和梯度，再实现一个线性分类器或小 MLP，最后进入实战二 CNN。

**如何验证：** 用一个 batch 完成前向和反向，确认至少一个参数梯度非空且 `optimizer.step()` 后参数发生变化；临时只取 32～64 个样本重复训练，训练 loss 应能明显下降并可近似记忆该小集合。不能过拟合小集合时，先查标签、损失输入、梯度和优化器参数。

### 阶段 4：CNN 图像分类与可靠检查点（第 5 周，约 8～10 小时）

**目标：** 完成一个从数据加载到最终测试的深度学习闭环。

**学习内容：**
- 卷积核、通道数、步幅、padding、池化如何影响特征图尺寸；全连接层与 logits。
- 图像归一化、交叉熵、AdamW；训练集增强与验证/测试确定性预处理的区别。
- 验证集选择最佳 epoch；模型保存、重载、推理模式；测试集一次性评估。
- CUDA AMP、GradScaler 的基本用途；显存不足时如何按优先级降低资源需求。

**动手与产物：** 完成实战二；保存最佳权重；新建独立小脚本加载权重，对一张测试图片输出预测类别；记录每个 epoch 的训练/验证 loss 与准确率。

**如何验证：** 权重重载前后同一输入的 logits 一致（允许浮点微小误差）；验证准确率显著高于 10 类随机水平；训练集和验证集指标都在日志里；能解释为何选择验证最佳权重，而不是最后一个 epoch。再检查一次 GPU 实际使用情况和峰值显存。

### 阶段 5：泛化、诊断和受控实验（第 6 周，约 6～8 小时）

**目标：** 能用证据判断欠拟合、过拟合或实验无效，并一次检验一个假设。

**学习内容：**
- 学习曲线与训练/验证差距；欠拟合、过拟合、数据分布偏移的表现。
- Dropout、weight decay、数据增强、学习率和训练时长分别可能改变什么。
- 混淆矩阵、每类召回率、置信度与错分图像；随机种子及复现实验的边界。
- 实验控制：固定划分、种子、基线和评估口径，每次只改变一个主要变量。

**动手与产物：** 完成实战二的 A/B/C 三个对照；绘制 loss/accuracy 曲线；查看至少 20 张错分图并归纳 2～3 类失败模式；选择一个改进并做验证集对照。

**如何验证：** 每项实验有事前假设、唯一主要改动、验证结果和结论；结果无提升也算有效，只要能说明证据；测试集不参与改进选择。能用曲线判断当前更像欠拟合还是过拟合，并提出下一项可证伪实验。

### 阶段 6：迁移学习和微调策略（第 7 周，约 8～10 小时）

**目标：** 学会复用预训练权重，并理解冻结参数、归一化和输入分布的影响。

**学习内容：**
- 预训练任务与目标任务的差异；分类头替换、冻结骨干、逐层解冻。
- 预训练权重的输入尺寸/均值/标准差；训练增强与验证预处理对齐。
- BatchNorm 的可训练参数与运行统计量是两件事；小数据集微调时的模式选择。
- 不同层使用不同学习率；冻结特征提取与全量微调的成本差异。

**动手与产物：** 完成实战三；固定 CIFAR-10 子集划分；比较冻结骨干与解冻 `layer4` 的验证表现、训练时间和显存；仅在最终方案确定后报告测试子集结果。

**如何验证：** 打印并检查可训练参数名称；确认分类头输出 10 类；解释两种变换的差异、BatchNorm 策略及分层学习率；记录数据划分索引/种子，使实验可复现。小验证集有波动时，在报告中明确样本量限制。

### 阶段 7：端到端项目与复现交付（第 8 周，约 8～10 小时）

**目标：** 把模型训练转化成另一个开发者能理解、运行和审查的项目。

**学习内容：**
- 从任务定义、数据许可和标签定义开始，设置简单基线与成功指标。
- 训练/验证/测试协议、预处理一致性、错误分析和适用边界。
- 推理接口、模型/配置/类别映射版本化；环境复现、日志与产物管理。
- 数据泄漏和线上分布变化风险；模型分数如何转成业务决策需另行定义。

**动手与产物：** 选择表格、图像或文本小任务，提交 README、训练入口、评估入口、锁定依赖、实验记录、模型权重或下载说明、样例预测和错误案例分析。

**如何验证：** 在新环境或干净目录按 README 从头运行；训练或评估脚本退出码为 0；相同数据划分下关键指标与记录接近；给定一个输入可输出标签/分数；报告清楚说明数据来源、测试结果、失败案例和限制。若只完成前三个实战，也至少对其中一个项目达到此标准。

**阶段通过总检查：** 不看笔记，能解释数据泄漏、验证集与测试集、loss 与指标、梯度更新、过拟合、最佳检查点和迁移学习；能定位一个“loss 不下降”问题；能从空环境重跑一个项目。每个阶段的证据建议放在 `outputs/` 或项目 README，形成代码、日志、图表和简短结论，而不是只勾选“看过资料”。

## 5. 实战一：表格数据二分类

**目标：** 用 scikit-learn 学会数据划分、预处理、模型比较和最终评估。这里使用内置乳腺肿瘤研究数据，适合作为教学案例，不能直接用作临床判断。

- 数据：569 个样本，30 个数值特征，不需要联网下载。
- 模型：多数类基线、逻辑回归、随机森林。
- 指标：Accuracy、F1、ROC-AUC、混淆矩阵。
- 计算设备：CPU 即可。

保存为 `01_tabular.py`：

```python
from pathlib import Path
import json
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (
    accuracy_score, classification_report, confusion_matrix,
    f1_score, roc_auc_score,
)
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler


def evaluate(model, x, y):
    pred = model.predict(x)
    prob = model.predict_proba(x)[:, 1]
    return {
        "accuracy": float(accuracy_score(y, pred)),
        "f1": float(f1_score(y, pred)),
        "roc_auc": float(roc_auc_score(y, prob)),
    }


def main():
    dataset = load_breast_cancer()
    # 约 60% 训练、20% 验证、20% 测试；分层划分保持类别比例。
    x_dev, x_test, y_dev, y_test = train_test_split(
        dataset.data, dataset.target,
        test_size=0.2, stratify=dataset.target, random_state=42,
    )
    x_train, x_val, y_train, y_val = train_test_split(
        x_dev, y_dev, test_size=0.25, stratify=y_dev, random_state=42,
    )
    models = {
        "majority_baseline": DummyClassifier(strategy="most_frequent"),
        "logistic_regression": make_pipeline(
            StandardScaler(), LogisticRegression(max_iter=2000, random_state=42)
        ),
        "random_forest": RandomForestClassifier(
            n_estimators=300, random_state=42, n_jobs=-1
        ),
    }
    validation = {}
    for name, model in models.items():
        model.fit(x_train, y_train)
        validation[name] = evaluate(model, x_val, y_val)
        print(name, "validation:", validation[name])

    # 按验证集 ROC-AUC 选模型，然后在开发集上重新拟合。
    best_name = max(validation, key=lambda name: validation[name]["roc_auc"])
    best_model = models[best_name]
    best_model.fit(x_dev, y_dev)
    test_metrics = evaluate(best_model, x_test, y_test)
    prediction = best_model.predict(x_test)
    print("Selected:", best_name)
    print("Test:", test_metrics)
    print("Confusion matrix (rows=true, columns=predicted):")
    print(confusion_matrix(y_test, prediction))
    print(classification_report(
        y_test, prediction, target_names=dataset.target_names, zero_division=0
    ))
    Path("outputs").mkdir(exist_ok=True)
    Path("outputs/tabular_metrics.json").write_text(
        json.dumps({
            "selected_model": best_name,
            "validation": validation,
            "test": test_metrics,
        }, indent=2), encoding="utf-8",
    )
    # 保存模型；仅加载自己信任的 pickle 文件。
    import pickle
    with open("outputs/tabular_model.pkl", "wb") as file:
        pickle.dump(best_model, file)
    print("Sample prediction:", dataset.target_names[
        best_model.predict(np.asarray(x_test[:1]))[0]
    ])


if __name__ == "__main__":
    main()
```


### 要观察和练习什么

1. 两个模型是否优于多数类基线？准确率相近时，ROC-AUC 是否也相近？
2. 数据中 `0 = malignant（恶性）`、`1 = benign（良性）`。代码的 F1 默认以类别 1 为正类，因此不能把这个 F1 直接叫作“恶性检出能力”。用分类报告查看恶性类别的召回率。
3. 标准化放在 Pipeline 中，只在训练数据上拟合。不能先对全数据 `fit_transform` 再划分。
4. 额外尝试逻辑回归的 `C=0.1、1、10`，只根据验证集挑选。确定方案后才报告最终测试表现。
5. 这个数据集较小，一次划分的结果可能波动。进阶时使用 `StratifiedKFold` 和 `cross_validate`，并保留独立测试集。

## 6. 实战二：用 CNN 识别服装图片

**目标：** 亲自完成 PyTorch 训练循环，理解 GPU、混合精度、验证集选择与模型保存。

- 数据：Fashion-MNIST，28×28 灰度服装图片，10 个类别。
- 划分：原训练集 60,000 张拆成 55,000 张训练、5,000 张验证；官方测试集 10,000 张保留作最终测试。
- 模型：两个卷积模块与分类层。
- 初始配置：batch size 128，训练 5 个 epoch。
- 显存：该网络规模很小，16GB 显存足够；实际用量以运行监控为准。

保存为 `02_fashion_cnn.py`：

```python
from pathlib import Path
import random
import torch
from torch import nn
from torch.utils.data import DataLoader, random_split
from torchvision import datasets, transforms


class FashionCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(1, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
            nn.Flatten(), nn.Linear(64 * 7 * 7, 128), nn.ReLU(),
            nn.Dropout(0.2), nn.Linear(128, 10),
        )

    def forward(self, x):
        return self.net(x)


@torch.inference_mode()
def evaluate(model, loader, device, loss_fn):
    model.eval()
    total_loss, correct, count = 0.0, 0, 0
    for x, y in loader:
        x, y = x.to(device), y.to(device)
        logits = model(x)
        total_loss += loss_fn(logits, y).item() * y.size(0)
        correct += (logits.argmax(1) == y).sum().item()
        count += y.size(0)
    return total_loss / count, correct / count


def main():
    random.seed(42)
    torch.manual_seed(42)
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    use_amp = device.type == "cuda"
    print("Device:", device)
    transform = transforms.Compose([
        transforms.ToTensor(), transforms.Normalize((0.5,), (0.5,)),
    ])
    full_train = datasets.FashionMNIST(
        "data", train=True, download=True, transform=transform
    )
    test_set = datasets.FashionMNIST(
        "data", train=False, download=True, transform=transform
    )
    train_set, val_set = random_split(
        full_train, [55000, 5000],
        generator=torch.Generator().manual_seed(42),
    )
    # 初次运行使用 0，兼容 Windows、WSL 和不同交互环境。
    options = dict(batch_size=128, num_workers=0, pin_memory=use_amp)
    train_loader = DataLoader(train_set, shuffle=True, **options)
    val_loader = DataLoader(val_set, shuffle=False, **options)
    test_loader = DataLoader(test_set, shuffle=False, **options)

    model = FashionCNN().to(device)
    loss_fn = nn.CrossEntropyLoss()
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
    scaler = torch.amp.GradScaler("cuda", enabled=use_amp)
    Path("checkpoints").mkdir(exist_ok=True)
    best_accuracy = -1.0

    for epoch in range(1, 6):
        model.train()
        total_loss, correct, count = 0.0, 0, 0
        for x, y in train_loader:
            x = x.to(device, non_blocking=use_amp)
            y = y.to(device, non_blocking=use_amp)
            optimizer.zero_grad(set_to_none=True)
            with torch.autocast(device_type=device.type, enabled=use_amp):
                logits = model(x)
                loss = loss_fn(logits, y)
            scaler.scale(loss).backward()
            scaler.step(optimizer)
            scaler.update()
            total_loss += loss.item() * y.size(0)
            correct += (logits.detach().argmax(1) == y).sum().item()
            count += y.size(0)

        val_loss, val_accuracy = evaluate(model, val_loader, device, loss_fn)
        print(
            f"epoch={epoch} train_loss={total_loss/count:.4f} "
            f"train_acc={correct/count:.4f} val_loss={val_loss:.4f} "
            f"val_acc={val_accuracy:.4f}"
        )
        if val_accuracy > best_accuracy:
            best_accuracy = val_accuracy
            torch.save(model.state_dict(), "checkpoints/fashion_best.pt")

    # 加载验证集表现最好的参数，再进行最终测试。
    model.load_state_dict(torch.load(
        "checkpoints/fashion_best.pt", map_location=device, weights_only=True
    ))
    test_loss, test_accuracy = evaluate(model, test_loader, device, loss_fn)
    print(f"test_loss={test_loss:.4f} test_acc={test_accuracy:.4f}")

    model.eval()
    x, y = test_set[0]
    with torch.inference_mode():
        logits = model(x.unsqueeze(0).to(device))
        probability = logits.softmax(dim=1)[0]
        confidence, predicted = probability.max(dim=0)
    print(
        "Example true:", test_set.classes[y],
        "predicted:", test_set.classes[predicted.item()],
        "probability:", round(confidence.item(), 4),
    )


if __name__ == "__main__":
    main()
```


### 如何理解训练循环

1. `model.train()`：启用训练行为，例如 Dropout。
2. `optimizer.zero_grad()`：清除上一步梯度，避免意外累积。
3. 前向计算：输入图片，输出 10 个类别的 logits。
4. `CrossEntropyLoss`：直接接收 logits 和整数标签，前面不要再加 Softmax。
5. `backward()`：计算参数梯度；这里通过 GradScaler 支持混合精度。
6. `optimizer.step()`：更新参数；混合精度时通过 `scaler.step()` 调用。
7. 验证时使用 `model.eval()` 和 `inference_mode()`，停止更新参数并关闭 Dropout。

训练中的准确率受 Dropout 和持续更新参数影响，因此不能要求它与验证准确率严格对应。预测时的 Softmax 数值也不保证是校准后的真实可信概率。

### 建议做的三个对照实验

| 实验 | 只修改的内容 | 观察重点 |
| --- | --- | --- |
| A | 学习率从 `1e-3` 改为 `1e-4` | 同样轮数下是否收敛更慢 |
| B | Dropout 从 `0.2` 改为 `0.5` | 训练、验证之间的差距如何变化 |
| C | epoch 从 5 增加到 10 | 验证损失是否在后期回升 |

每次修改后使用不同检查点名称或输出目录，避免覆盖结果。对照阶段根据验证集比较；可以把脚本末尾的测试部分暂时移到单独的最终评估脚本，避免每次实验都查看测试结果。

**完成标准：** 程序正常完成、验证表现明显高于 10 类随机猜测的约 10%、检查点可以重新加载，并能解释训练损失和验证损失的变化。常见实现可以达到较高准确率，但具体数值受轮数、随机种子和版本影响，不把某个固定分数作为运行保证。

## 7. 实战三：预训练 ResNet18 做迁移学习

**目标：** 学会利用已经学过大量图片的网络，在新任务上训练一个小分类头。

- 数据：CIFAR-10，10 类彩色图片。
- 为缩短初次练习，从官方训练集固定抽取 10,000 张训练、2,000 张验证；从官方测试集抽取 2,000 张最终测试。未选中的样本在这个入门实验中不用。
- 模型：ImageNet 预训练 ResNet18，冻结骨干，仅训练最后的全连接层。
- 图片：将 32×32 放大到 128×128，降低相对 224×224 输入的计算量。这是练习中的取舍，放大不会增加原图细节。
- 使用预训练权重要求的 ImageNet 均值与标准差；首次运行需要下载权重。

保存为 `03_transfer_cifar10.py`：

```python
from pathlib import Path
import torch
from torch import nn
from torch.utils.data import DataLoader, Subset
from torchvision import datasets, models, transforms


@torch.inference_mode()
def accuracy(model, loader, device):
    model.eval()
    correct, count = 0, 0
    for x, y in loader:
        x, y = x.to(device), y.to(device)
        correct += (model(x).argmax(1) == y).sum().item()
        count += y.size(0)
    return correct / count


def main():
    torch.manual_seed(42)
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    use_amp = device.type == "cuda"
    mean = (0.485, 0.456, 0.406)
    std = (0.229, 0.224, 0.225)
    train_transform = transforms.Compose([
        transforms.Resize((128, 128)),
        transforms.RandomHorizontalFlip(),
        transforms.ToTensor(), transforms.Normalize(mean, std),
    ])
    eval_transform = transforms.Compose([
        transforms.Resize((128, 128)),
        transforms.ToTensor(), transforms.Normalize(mean, std),
    ])
    # 相同训练数据的两个视图：只有训练视图执行随机增强。
    train_view = datasets.CIFAR10(
        "data", train=True, download=True, transform=train_transform
    )
    val_view = datasets.CIFAR10(
        "data", train=True, download=True, transform=eval_transform
    )
    test_view = datasets.CIFAR10(
        "data", train=False, download=True, transform=eval_transform
    )
    generator = torch.Generator().manual_seed(42)
    indices = torch.randperm(len(train_view), generator=generator).tolist()
    test_indices = torch.randperm(len(test_view), generator=generator).tolist()
    train_set = Subset(train_view, indices[:10000])
    val_set = Subset(val_view, indices[10000:12000])
    test_set = Subset(test_view, test_indices[:2000])
    options = dict(batch_size=64, num_workers=0, pin_memory=use_amp)
    train_loader = DataLoader(train_set, shuffle=True, **options)
    val_loader = DataLoader(val_set, shuffle=False, **options)
    test_loader = DataLoader(test_set, shuffle=False, **options)

    model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)
    for parameter in model.parameters():
        parameter.requires_grad = False
    model.fc = nn.Linear(model.fc.in_features, 10)
    model = model.to(device)
    optimizer = torch.optim.AdamW(model.fc.parameters(), lr=1e-3)
    loss_fn = nn.CrossEntropyLoss()
    scaler = torch.amp.GradScaler("cuda", enabled=use_amp)
    best_accuracy = -1.0
    Path("checkpoints").mkdir(exist_ok=True)

    for epoch in range(1, 6):
        # 骨干保持 eval，避免冻结参数后 BatchNorm 仍更新运行统计量。
        model.eval()
        model.fc.train()
        total_loss, count = 0.0, 0
        for x, y in train_loader:
            x = x.to(device, non_blocking=use_amp)
            y = y.to(device, non_blocking=use_amp)
            optimizer.zero_grad(set_to_none=True)
            with torch.autocast(device_type=device.type, enabled=use_amp):
                logits = model(x)
                loss = loss_fn(logits, y)
            scaler.scale(loss).backward()
            scaler.step(optimizer)
            scaler.update()
            total_loss += loss.item() * y.size(0)
            count += y.size(0)
        val_accuracy = accuracy(model, val_loader, device)
        print(
            f"epoch={epoch} train_loss={total_loss/count:.4f} "
            f"val_acc={val_accuracy:.4f}"
        )
        if val_accuracy > best_accuracy:
            best_accuracy = val_accuracy
            torch.save(model.state_dict(), "checkpoints/cifar10_transfer_best.pt")

    model.load_state_dict(torch.load(
        "checkpoints/cifar10_transfer_best.pt", map_location=device,
        weights_only=True,
    ))
    print(f"test_subset_acc={accuracy(model, test_loader, device):.4f}")


if __name__ == "__main__":
    main()
```

### 继续怎么改进

1. 固定数据划分，先把当前方案作为基线。
2. 只把输入从 128 改到 224，比较验证准确率、训练时间和显存。
3. 再尝试解冻 `layer4`，把分类头学习率设为 `1e-3`、`layer4` 设为 `1e-4`，重新创建包含这些参数的优化器。
4. 解冻时还要明确 BatchNorm 的策略：小批量下可继续保持骨干为 `eval()`，其可训练参数仍能计算梯度；若改为 `train()`，运行均值和方差也会变化。不要只改 `requires_grad` 而忽略这些行为。
5. 最后扩展到完整训练集，保留验证集和官方测试集。当前输出是固定测试子集准确率，不能直接与使用完整测试集的公开成绩比较。

**完成标准：** 能解释预训练权重来自哪里、哪些参数在更新、为什么训练与验证变换不同，以及冻结 BatchNorm 统计量的原因。

## 8. 4060 Ti 16GB 的实用训练设置

### 8.1 从这些设置起步

| 设置 | 建议起点 | 何时调整 |
| --- | --- | --- |
| 数值精度 | CUDA 下使用 AMP；本文使用默认 FP16 autocast + GradScaler | 非有限损失时检查数据、学习率，再考虑关闭 AMP 定位 |
| batch size | 小型 CNN 128；迁移学习 64 | OOM 时减半，稳定后再尝试增大 |
| DataLoader worker | 先用 `num_workers=0` | 跑通后比较 2、4 是否更快，注意内存增长 |
| 图片尺寸 | 按任务从 28、128 等小尺寸开始 | 需要细节且资源允许时增大 |
| 优化器 | AdamW | 熟悉基线后再比较 SGD 等方案 |
| 检查点 | 保存验证集表现最好的模型 | 长训练额外保存完整恢复状态 |

这些是起点，不是所有模型通用的最优配置。卷积模型的速度还取决于 CPU、数据盘、变换耗时和软件版本；不要按 GPU 型号承诺固定训练时间。

### 8.2 显存不足时按顺序处理

遇到 `CUDA out of memory`：

1. 用 `nvidia-smi` 查看是否有其他进程占用 GPU。
2. 把 batch size 减半，例如 `128 → 64 → 32`。
3. 确认已经启用 AMP。
4. 图像任务减小输入尺寸；文本任务减小序列长度。
5. 需要更大有效 batch 时使用梯度累积；需要更大模型时再学习梯度检查点。
6. 检查是否把带计算图的 `loss`、`logits` 不断加入列表。记录数值用 `loss.item()`，保存预测可使用 `detach().cpu()`。

`torch.cuda.empty_cache()` 只能释放未使用的缓存，不能释放仍被张量占用的显存，通常不能修复模型本身超出显存的问题。

### 8.3 梯度累积是什么意思

例如单次只能放 16 个样本，累积 4 次再更新，相当于用约 64 个样本的梯度更新一次。通常需要按累积步数缩放 loss，并正确处理最后不足 4 步的一组。它与真实 batch size 64 不完全等价，BatchNorm 等操作会受到小批量的影响。入门代码先不加这一层复杂度。

### 8.4 如何监控

Linux / WSL 中可以在第二个终端运行：

```bash
watch -n 1 nvidia-smi
```

Windows 可以直接多次执行 `nvidia-smi` 或使用任务管理器的 CUDA/计算视图。

- GPU 利用率低：检查是否在下载数据、是否实际用了 CPU、数据加载是否太慢。小模型的 GPU 利用率波动正常。
- GPU 显存使用多：不一定有问题；关注是否有持续增长、OOM 或明显变慢。
- 系统内存高：减小 worker 数，不要提前把全部图片展开为大张量。

## 9. 实验记录、评估与模型保存

### 9.1 每次只改变一个主要因素

建议将下面模板保存在 `outputs/实验记录.md`：

| 实验 | 数据划分/种子 | 模型 | 学习率 | batch | epoch | 验证指标 | 耗时 | 峰值显存 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 001 | 固定划分 / 42 | FashionCNN | 0.001 | 128 | 5 | 待填写 | 待填写 | 待填写 | 初始基线 |

记录模型选择依据、数据版本、增强方式与环境版本。不要为了获得更高分，反复根据测试集调整模型；如果已经这样做，测试集就参与了开发，需要另找独立数据做最终评估。

随机种子能减少部分差异，但不保证跨 GPU、驱动和框架版本逐位一致。有明显随机波动时，用多个种子重复实验，报告均值和范围。

### 9.2 不只看一个准确率

- 类别不均衡：增加宏平均 F1、每类召回率、混淆矩阵。
- 回归：用 MAE、RMSE，并观察预测与真实值的散点图。
- 图像分类：查看错分图片，区分相似类别、背景干扰、低画质与错误标签。
- 比较训练损失和验证损失，判断是否过拟合或还未收敛。
- 同一用户、病人、设备或同一原始图片产生的样本，应按来源分组划分；时间序列通常按时间划分。随机逐条划分可能泄漏信息。

### 9.3 保存什么才够

本文深度学习脚本保存 `state_dict`，适合重新构建相同模型后推理。长期训练若要可靠恢复，还应保存：

- 模型参数、优化器状态、GradScaler 状态、调度器状态。
- 当前 epoch、全局步数、最佳验证指标、随机数状态。
- 类别顺序、预处理、模型结构配置和数据划分信息。

推理脚本必须使用与训练一致的输入格式、归一化和类别顺序。仅加载可信来源的模型文件，优先使用 `state_dict` 与支持的 `weights_only=True` 加载方式。

## 10. 常见问题速查

| 问题 | 常见原因 | 优先操作 |
| --- | --- | --- |
| `torch.cuda.is_available()` 是 False | 驱动、WSL 配置或安装了 CPU wheel | 检查 `nvidia-smi`、当前 Python 环境和官方安装命令 |
| CUDA wheel 无法使用 | 驱动与运行时不兼容 | 按官方要求更新驱动或选择兼容 wheel |
| 数据或权重下载失败 | 网络或缓存不完整 | 检查原始报错、下载来源与缓存文件 |
| DataLoader 卡住或 worker 报错 | 多进程或环境限制 | 先用 `num_workers=0`，保留 main 入口 |
| loss 不下降 | 学习率、标签、数据或训练循环有问题 | 先尝试拟合几十个样本，检查标签范围和梯度 |
| loss 为 NaN | 输入非有限值、学习率过高或数值问题 | 检查数据，降低学习率，关闭 AMP 对照定位 |
| 训练很好，验证差 | 过拟合或训练验证分布不同 | 检查划分、增强和归一化，增加数据或正则化 |
| 验证一直随机水平 | 标签映射、输出维度或模型更新错误 | 确认 10 类输出、整数标签和优化器参数 |
| 模型加载时报尺寸不匹配 | 网络结构或类别数不一致 | 使用保存时的模型定义和类别数量 |
| 预测类别顺序错乱 | 自定义数据集标签映射不一致 | 保存并复用 `class_to_idx` |

“拟合几十个样本”是调试手段：暂时关闭强增强与 Dropout，在极小训练集上检查模型是否能把训练误差降下来。它不能证明模型能泛化。

## 11. 中文学习资源与阅读顺序

1. **《动手学深度学习》中文版（PyTorch）**：<https://zh.d2l.ai/>。先看预备知识、线性神经网络、多层感知机、卷积神经网络与优化算法；不要一开始逐章通读所有内容。
2. **NumPy 快速入门**：<https://numpy.org/doc/stable/user/quickstart.html>。只需按需查数组形状、索引、广播和向量化，不必重新学习 Python 语法。
3. **《机器学习》周志华著**：建立传统机器学习概念，适合配合实战查阅；数学较密，可以放在跑通第一个项目之后。
4. **《统计学习方法》李航著**：希望进一步理解算法与推导时阅读，作为第二阶段资料。
5. **PyTorch 官方教程**：<https://pytorch.org/tutorials/>。以英文原文为接口依据，必要时使用浏览器翻译，重点阅读基础训练流程和迁移学习教程。
6. **scikit-learn 官方指南**：<https://scikit-learn.org/stable/user_guide.html>。查 Pipeline、数据预处理、交叉验证和指标；可辅助浏览器翻译。

中文教程可能使用旧版 API。出现 AMP、权重加载或 torchvision 权重参数差异时，以当前安装版本的官方文档为准。
